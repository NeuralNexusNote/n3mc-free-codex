# N3MemoryCore Free Codex版 (n3mc-free-codex) v1.9.2

**Codexに、会話をまたいで使える記憶を。無料で、あなたのPCの中に。**

新しいチャットや別のプロジェクトで、以前の決定と理由をもう一度説明していませんか。
N3MemoryCoreは、あなたの発言とCodexの返答をPCに保存し、関係する話をしたときに呼び出します。
毎回「覚えて」と頼む必要はありません。信頼した2つのフックが保存と検索を行います。
N3MCが受け持つのは**会話履歴の層**です。`AGENTS.md`などのいつも使う指示と組み合わせて使えます。

配布の中心は**指示書**です。あなたのCodexにコードを生成してもらい、設定と動作確認まで行います。

**初めて使う方へ。** 下の手順で Free を生成したら、同じプロジェクトの新しいチャットで「試作用の表紙は青に決めました」と伝えます。もう一つ新しいチャットで「試作用の表紙は何色に決めましたか」と尋ね、答えと検索された記録を確認してください。生成したソースと `tests/` は、後で Pro にアップグレードするときにも使います。

1. エクスプローラーで専用の空フォルダを作る。
2. そのフォルダに指示書 `N3MemoryCore_v1.9.2_Free_JP.md` を入れる。
3. Codexで、そのフォルダをローカルの作業フォルダとして開く。
4. 「この指示書に従って、実装・セットアップ・確認テストまで行ってください」と送る。
5. Codexが登録した2つのフックを **Settings → Hooks**（CLIでは `/hooks`）で確認して信頼する。その後のテストはCodexが実行する。

新しいチャットでの保存と別チャットからの取り出しを含むテストに合格したことを、Codexの **Evidence Report** で確認してください。詳しくは[セットアップ](#セットアップ)をご覧ください。

## 仕組み

```text
あなたの発言 → 過去の記憶を検索 → 今回の発言を保存
                         ↓
                  検索結果をCodexへ渡す
                         ↓
                    Codexが回答
                         ↓
                  Stopフックが返答を保存
```

Codexのフック機能を利用し、すべて自動で行われます。ユーザーが意識する必要はありません。

- **保存するもの** — フックで受け取った対象の発言と返答を保存します。長文は分割します。明示的な保存拒否と、秘密情報と判定された入力は除外します。コードブロック（``` で囲んだ部分）は `[code omitted]` として保存します。N3MC が覚えるのは、話したことと決めたことです。コードは、プロジェクトのファイルにあります。
- **呼び出すもの** — 発言のたびに、フックが記憶を検索します。関係のある記録を、Codex があなたの発言を読む前に、コンテキストに加えます。

### 3 つの場面

> **月曜** — Codex と相談して、サイトのデータベースを PostgreSQL にすると決めます。理由も話します。
>
> **水曜** — 新しいセッションで、「データベースは何にしたか」と聞きます。月曜の決定と理由が、質問と一緒に Codex に届きます。説明し直す必要はありません。
>
> **金曜** — 別のフォルダで作業しています。その話題になると、月曜の決定がここでも呼び出されます。Free は、すべてのプロジェクトのフォルダで 1 つの記憶を使います。

### Codexに届く記憶の例

検索結果の表示形式の例です。接続先にあるClaude Codeの記録も検索できます。保存元のエージェント名と、保存形式上の応答ラベル `[claude]` は保持されます。

```text
# Recalled Memory Context
Search query: サイトのデータベースは、何にすると決めましたか。理由も教えてください。

## Top matches (use these to answer the question)

_If several versions of the same content appear, the one with the newest `saved` time is the current one._

## [1] score=0.5472 saved=2026-11-22 15:59 (UTC+0900) claude-code
[user] サイトのデータベースは PostgreSQL にしましょう。複数の人が同時に編集する予定で、SQLite は書き込みのたびにファイル全体をロックするからです。

## [2] score=0.4779 saved=2026-11-22 15:59 (UTC+0900) claude-code
[claude] 承知しました。データベースは PostgreSQL にします。理由は、同時に編集する人がいることと、SQLite は書き込みが 1 つずつになることです。次は、記事のテーブルの定義を書きます。

## Previous matching Q-A exchanges (supplementary context)

### turn_id: 378a62f3-fff4-4233-9a97-1044f17bf86d saved=2026-11-22 15:59 (UTC+0900)
[user] サイトのデータベースは PostgreSQL にしましょう。複数の人が同時に編集する予定で、SQLite は書き込みのたびにファイル全体をロックするからです。
[claude] 承知しました。データベースは PostgreSQL にします。理由は、同時に編集する人がいることと、SQLite は書き込みが 1 つずつになることです。次は、記事のテーブルの定義を書きます。
```

`Top matches` は、関連度の下限を通った記録です。下限を通った記録が少ないときは、落ちた記録のうち近いものが `Possibly related` という見出しで加わります。最後の部分は、上位の記録が入っているやりとりの全体です。

### Codexの指示と会話記憶の役割分担

| | `AGENTS.md`などの指示 | N3MemoryCore |
|---|---|---|
| 主な役割 | 作業の決まりや、いつも伝えたい情報を示す | 過去の発言・返答と、そのときの理由を残す |
| 使い方 | 必要な指示を利用者が管理する | フックが会話を保存し、関連する場面で検索する |
| 注意点 | 常時必要な指示を明確にする | 検索結果に依存するため、必ず思い出せるとは限らない |

毎回必要な決まりは指示ファイルへ、会話の流れや決定理由はN3MCへ、という使い分けができます。

## FreeとLite、どちらを使うか

無償のN3MemoryCoreにはFreeとMCP Liteがあります。このREADMEは**Free Codex版**のものです。

| | Free Codex版 | [N3MC MCP Lite](https://github.com/NeuralNexusNote/n3mcmcp-lite) |
|---|---|---|
| 使い方 | Codexのフックで保存・検索 | MCP対応アプリから記憶ツールを呼ぶ。対応する版にはClaude Code用フックもある |
| 保存 | 対象の発言と返答を自動保存 | MCPではAIが保存を判断。フック対応版では会話を自動保存 |
| 保持期間 | 期限なし | 7日で自動削除 |
| 必要なもの | Python 3.10以上 | Python 3.10以上とDocker（Redis Stack） |
| 導入 | Codex用指示書から生成・設定 | 利用するアプリに対応したLiteの指示書・設定を使う |

- **Free Codex版** — Codexの会話を長期に残したい場合。通常の保存・検索にMCP接続やDockerは使いません。
- **MCP Lite** — MCP対応アプリでも使いたい場合や、短期間で消える作業メモリが必要な場合。対応するクライアントと必要なソフトを確認してください。

**Free Codex版が向かない用途:**

- Codex以外のアプリからMCPツールとして使うこと。
- 古い記録の自動削除や、記録1件ごとの削除。Freeにはこれらのコマンドがありません。
- 複数のPC間での自動同期。Free Codex版には同期機能がありません。

## 特徴

| したいこと | N3MemoryCore がすること | 仕組み |
|---|---|---|
| 同じ説明を繰り返したくない | 発言と返答をすべて保存し、関係のあるものを毎ターン呼び出す | Codex のフック（`UserPromptSubmit`、`Stop`）。ツールの呼び出しも、手作業も要らない |
| 自分の言葉で探したい | 言い回しが違っても、関係のある過去の会話を見つける | `intfloat/multilingual-e5-base` のベクトル検索（日本語・英語・中国語・韓国語など約 100 言語）と、キーワード検索 |
| 翌日、続きから始めたい | セッションをまたいでも、プロジェクトのフォルダが違っても、記憶が残る | すべてのフォルダで 1 つの DB。今の会話の記録を先に並べる |
| データを手元に置きたい | 記憶を自分の PC のファイルに保存し、クラウドのサービスには置かない | SQLite。Codex に送られるのは、そのターンに呼び出した記憶だけで、メッセージと一緒に送られる（[詳しく](#記憶はあなたの-pc-に残ります)） |
| トークンを節約したい | 検索はローカルの埋め込みで行い（Codex のトークンは使わない）、関係のある記録だけを差し込む | 差し込む塊には上限がある（`top_matches_max`、`min_results`） |
| 複数のエージェントで 1 つの記憶を使いたい | 記録ごとに、書いたエージェントを残す | `agent_name`・`local_id`。エージェント自身の記憶を先に並べる機能は Pro 版のもの |
| 既存のFree／Proと記憶を共有したい | 同じPCの確認済みサーバーへ保存・検索する | 接続先のデータルートとポートを指定する（下の接続設定を参照） |

ほかの埋め込みモデルを使うときは、`config.json` に書いて `n3mc-free-codex --reembed` を実行します。768 次元のベクトルを出すモデルである必要があります。

## 記憶はあなたの PC に残ります

AI が覚えていてくれるのは便利ですが、その記憶がどこに置かれるのかは気になるところです。N3MemoryCore は、記憶をあなたが管理できる 1 か所、つまりあなたの PC の中のフォルダに置きます。

- **ローカルの 1 ファイル** — 単独運用の記憶は、SQLite のファイル `~/.n3mc-free-codex/.memory/n3memory.db` 1 つに保存されます。N3MC のアカウントも、N3MC のクラウドサービスもありません。置き場所は `N3MC_FREE_CODEX_HOME` で変えられます([オプション: データ位置の変更](#オプション-データ位置の変更))。
- **入力の原文も、その隣に残る** — `~/.n3mc-free-codex/.memory/audit.log` に、除外されなかったフック入力の原文（あなたの発言と Codex の返答。コードブロックも含む）が残ります。50 MB で入れ替わります。`n3mc-free-codex --list` には出ません。DB と同じく、他人に見せない情報として扱ってください。
- **検索は PC の中で動く** — 埋め込みモデルも検索も、手元で動きます。N3MC のサーバーは `127.0.0.1` だけで待ち受け、ほかのホスト名あての要求は断ります。同じネットワークのほかの機械からは使えません。
- **利用状況を送らない** — N3MC は利用データをどこにも送りません。コードは公開されているので、ご自身で確かめられます。
- **中身を見られる・消せる** — `n3mc-free-codex --list` で保存された内容を表示できます。`~/.n3mc-free-codex/` を消せば、すべて消えます([アンインストール](#アンインストール))。バックアップは 2 つのファイルをコピーするだけです([バックアップと復元](#バックアップと復元))。

ネットワークを通るもの:

- **埋め込みモデルのダウンロード** — 最初の検索のときに、`intfloat/multilingual-e5-base`(約 1.1 GB)を Hugging Face から取得します。その後も、モデルを読み込むときに Hugging Face のライブラリが更新を確認することがあります。ダウンロードが済んだ後に `HF_HUB_OFFLINE=1` を設定すると、この確認は止まります。
- **Codex が読む部分** — そのターンに呼び出された記憶はプロンプトに加えられるので、Codex に入力した文と同じように、メッセージと一緒に OpenAI に送られます。N3MC が記憶の DB をどこかに上げることはありませんが、Codex がそのターンに使う部分は会話の一部になります。

接続運用では記憶の保存先は接続先サーバーになり、Codex側の監査ログはローカルに残ります。

## セットアップ

**方法Aの指示書から作成する導入がメイン**です。方法Bは、参考コードをそのまま使いたい方向けです。

### 方法A：指示書から作成（メイン・推奨）

1. **専用フォルダを作る** — 空のフォルダを用意します。例: `C:/Users/<あなたの名前>/n3mc-free-codex`。生成したコードは、その後もこのフォルダで使います。
2. **指示書を入れる** — `N3MemoryCore_v1.9.2_Free_JP.md`を入れます。別のプロジェクトのファイルは混ぜません。
3. **Codexで開く** — そのフォルダをローカルの作業フォルダとして開きます。
4. **実装を頼む** — 次の依頼を送ります。

```text
この指示書 N3MemoryCore_v1.9.2_Free_JP.md に従って、N3MemoryCore Free Codex版を実装してください。前提条件の確認、インストール、フック登録、§6・§7の確認テストまで行ってください。フック登録後、私が確認して信頼する対象の2つを示してください。信頼後のテスト入力と確認コマンドも自分で実行し、Evidence Reportで結果を報告してください。
```

Codexは導入先を確認し、Pythonと依存関係を確かめてからコード生成・インストール・登録を行います。すでに了承した導入先の再確認は不要です。別のプロジェクトを上書きしません。

5. **2つのフックを信頼する** — **Settings → Hooks**（CLIでは `/hooks`）で、`N3MC-Free-Codex memory` の `UserPromptSubmit` と `Stop` を確認して信頼します。
6. **確認結果を見る** — 信頼後はCodexが新しいチャットを使って試験します。§6.1・§6.2の3ターンの自動保存、別チャットからの検索、保存しない指定、および§7のテスト結果を確認してください。

**コード生成やフック登録だけでは、セットアップ完了ではありません。必要な確認に合格したEvidence Reportまで確認してください。** 未確認の項目があれば、その項目の確認が必要です。

最初のモデル取得には数分かかる場合があります。編集可能インストールでは生成したフォルダを使い続けるため、あとから消したり移したりするとフックが動かなくなります。

### 方法B：参考コードから導入（おまけ）

#### 1. インストール

```bash
git clone https://github.com/NeuralNexusNote/n3mc-free-codex.git
cd n3mc-free-codex
python -m pip install -e ".[test]"
```

Python 3.10以上が必要です。初回は埋め込みモデルを取得します。

#### 2. Codexに接続する

```bash
n3mc-free-codex --init
```

- データフォルダ `~/.n3mc-free-codex` と `config.json` を作り、`owner_id`・`local_id`を用意します。単独運用ではDBも初期化します。
- ユーザー設定の `~/.codex/hooks.json` に、`UserPromptSubmit` と `Stop` を登録します。`CODEX_HOME`を変えている場合は、そのフォルダの `hooks.json` を使います。
- 導入したPythonの絶対パスでフックを起動し、それぞれに120秒の制限時間と `N3MC-Free-Codex memory` の表示名を付けます。
- 他のハンドラーを保持し、変更前にバックアップします。不正なJSONは書き換えず、再実行しても本版の登録は重複しません。

フックの信頼はこのコマンドだけでは完了しません。Codexの承認・サンドボックス設定は利用者の設定を使います。

#### 3. フック登録を検証する

Codexに、登録先・実行するPython・両イベントの登録が各1件であること・120秒の制限時間を確認してもらいます。方法Bで自分で調べる場合は、次のコマンドが `OK` を返すことを確認できます。

```bash
python -c "import os,json,base64,re; from pathlib import Path; p=Path(os.environ.get('N3MC_CODEX_HOOKS_PATH') or str(Path(os.environ.get('CODEX_HOME') or str(Path.home()/'.codex'))/'hooks.json')).expanduser(); h=json.loads(p.read_text(encoding='utf-8-sig')).get('hooks',{}); norm=lambda c: base64.b64decode(c.rsplit(' ',1)[-1]).decode('utf-16le') if '-EncodedCommand ' in c else c; groups=[[x for g in h.get(e,[]) for x in g.get('hooks',[]) if x.get('type')=='command' and re.search(r'(?<![A-Za-z0-9_.-])n3memorycore_free_codex[.]codex_entry(?![A-Za-z0-9_.-])',norm(x.get('command',''))) and re.search(r'(?<![A-Za-z0-9_-])'+f+r'(?![A-Za-z0-9_-])',norm(x.get('command','')))] for e,f in [('UserPromptSubmit','--prompt'),('Stop','--stop')]]; assert all(len(g)==1 and g[0].get('timeout')==120 for g in groups), 'Free Codex hook registration missing, duplicated or invalid'; print('OK')"
```

`OK`は登録形式の確認です。信頼済みであることや会話が保存されたことまでは証明しません。登録が欠けている場合は、同じPythonで `n3mc-free-codex --init` を再実行します。

#### 4. フックを確認して信頼する

**Settings → Hooks**（CLIでは `/hooks`）で、`N3MC-Free-Codex memory` の `UserPromptSubmit` と `Stop` を確認して信頼します。その後、導入先とは別の作業フォルダで新しいチャットを開始します。

#### 5. 動作確認

Codexに指示書の§6.1・§6.2を実行してもらいます。3ターンすべてに入力 `[user]` と応答 `[claude]` があり、各組の `turn_id` が一致し、ターンごとに異なることを確認します。`agent_name` は `codex`、同じチャットの `session_id` は共通です。手動の `--buffer` で代用しません。

```bash
n3mc-free-codex --list --format jsonl
```

答えの値を質問に含めない別チャットで取り出せること、保存しないと指定した入力と応答が記録されないこと、§7の自動テストの結果も確認します。接続運用では接続先DBで確認します。

#### オプション: データ位置の変更

`N3MC_FREE_CODEX_HOME` に保存先の絶対パスを指定します。`--init`の前に、Codexと確認用ターミナルの両方へ同じ設定が届くようにしてください。ターミナルだけの設定は、別に起動したCodexへ引き継がれません。環境変数を変更したら、それを読み込むようCodexとターミナルを開き直します。

### トラブルシューティング

**`n3mc-free-codex: command not found`**
導入したPythonの `Scripts/`（Windows）または `bin/`（Linux）がPATHにない可能性があります。同じPythonで `python -m n3memorycore_free_codex.n3memory --init` を使えます。別のPythonへ切り替わっていないかも確認します。

**登録できたが何も保存されない**
両フックの信頼状態、実行エラー、登録されたPythonの場所、データルートをCodexに確認してもらいます。接続運用ではCodex版の `--list` は接続先を読みません。接続先のDBを確認してください。通常のターンでは `.memory/audit.log` に監査が残ります。保存拒否・秘密情報の除外時は監査も残しません。

**入力だけがあり、応答がない**
`Stop`の実行結果を確認します。入力と応答があっても別チャットで検索できない場合は、そのチャットの `UserPromptSubmit` の出力を確認します。

**初回の検索が使えない**
モデルの取得・読み込みに時間がかかっている場合があります。エラーとデータフォルダの `.memory/server.log` を確認します。検索できない状態を、保存完了や動作確認済みとは扱いません。

### セットアップ後の体験

- 発言に関係する過去の会話が検索され、Codexに渡されます。
- 発言と返答はフックで保存され、毎回の手動保存は不要です。
- 記憶を回答に実際に使ったときは、短い想起の告知があります。
- 保存が失敗した場合は通知します。成功した自動保存ごとの報告は行いません。

### 検索の設定

単独運用の設定は `~/.n3mc-free-codex/config.json` にあります。主な設定と意味は指示書を参照してください。接続運用では接続先の検索設定を使います。

### バックアップと復元

`.memory/n3memory.db`（記憶データ）と `config.json`（`owner_id`・`local_id`を含む設定）をセットで保管します。稼働中のDBはSQLiteのバックアップ機能を使うか、対象の単独サーバーを止めて整合性のあるコピーを作ります。復元時も同じデータルートに両方を戻します。

原文も必要なら `audit.log` と `audit.log.1` も保管します。接続運用では接続先のDB・設定とCodex側の監査をそれぞれバックアップします。

### アンインストール

Codexに「N3MemoryCore Free Codex版を削除してください。記憶データは残してください」と頼めます。自分で行う場合は次の順です。

1. Codexの設定から本版の `UserPromptSubmit` と `Stop` の登録だけを取り除き、他製品のフックは残します。
2. 単独運用の本版サーバーが動いていれば、実行コマンドとデータルートを照合して、そのサーバーだけを止めます。接続先のFree／Proは止めません。
3. 導入に使ったPythonでパッケージを外します。

```bash
python -m pip uninstall n3memorycore-free-codex
```

4. データフォルダは復元用に保持します。記憶も消す場合だけ、バックアップを確認して対象のデータフォルダを削除します。削除したデータは元に戻せません。

### 本体Free／Proの常駐サーバーへの接続

すでに同じPCで本体のFree／Proを使っている場合は、そのサーバーへ接続して会話を保存・検索できます。Codex側の `config.json` に接続先のポートとデータフォルダの絶対パスを設定します。

```json
{
  "connect_server_port": 18521,
  "connect_server_root": "C:/Users/<あなたの名前>/.n3mc-pro"
}
```

これはProの設定例です。両方の値を実際の接続先に合わせ、接続先を先に起動しておきます。両方を解除すると単独運用に戻ります。

- 接続先を確認できた場合だけ、そのDBへ保存・検索します。接続先の起動・停止・修復は行いません。
- Codex側には監査ログを残し、記録をローカルDBへ二重保存しません。接続先が使えない場合も別のDBへ退避しません。
- Codex版の `--list`・`--show-turn`・`--recall-thread` はローカル用です。接続先の全文は、接続先製品のCLIとデータルートで読みます（指示書§3）。
- 単独の記録は `--list --format jsonl` で全IDを出力できます。移行時にどのIDが残るかは取り込み側の仕様なので、一時データで確認してください。

## ID 階層構造

N3MemoryCore は 6 つの ID フィールドで各レコードの出所と文脈を識別します：

| ID | 保存場所 | 生成タイミング | 粒度 | 用途 |
|---|---|---|---|---|
| `id` (PK) | DB レコード | レコード作成時 (UUIDv7, 時系列順) | **1 レコード** | 各記憶の一意識別子 |
| `owner_id` | `config.json` | 初回起動時 (UUIDv4) | **所有者 / データフォルダ** | データの所有者識別 — 共有・マルチユーザーシナリオ・インポート由来の記録に使用 |
| `local_id` | `config.json` / API | 初回起動時 (UUIDv4)、またはリクエスト毎 | **インストール** | 1 つの Codex のインストールに 1 つ。どのセッションでも同じ値。全レコードに保存する（Free 版ではランキングには使用されない；`b_local` は Pro 機能） |
| `session_id` | Codex から渡される（フックの入力）。なければプロセスごとに作る | 会話ごと | **1 つの会話** | 同じ会話の記憶をまとめる。Free 版では `b_session` ランキングバイアス（一致=1.0、不一致=0.6）を駆動し、進行中の会話を、関係のない過去のセッションより優先する |
| `turn_id` | DB レコード | Codexのフックイベントが渡す | **1 つのやりとり** | 1 つの発言と、それに答える返答を結ぶ。`--show-turn` と `--recall-thread` に渡す |
| `agent_name` | DB レコード | 保存ごと (任意文字列) | **表示名** | 書いたものの人間可読なラベル（Codexのフックは `"codex"`）。`--buffer --agent-id <name>` はこのフィールドを入れる |

```
owner_id  (データフォルダ ~/.n3mc-free-codex と、その所有者)
  └── local_id  (インストール。どのセッションでも同じ)
        └── session_id  (Codex の 1 つの会話)
              └── turn_id  (1 つのやりとり: 1 つの発言と、その返答)
                    └── id  (1 件のレコード = 1 つのチャンク)

agent_name  (表示用のラベル。階層の外。Codexのフックは "codex")
```

## 動作環境

- コマンドフックに対応したローカルの**Codex**。
- **Python 3.10以上**。不足する前提条件は指示書に従ってCodexが案内します。
- **対象OS**: Windows 11・Ubuntu。macOSは対象外です。

## 拡張性

必要な拡張をCodexに相談できます。以下は指示書を変更して追加する用途の例であり、標準のFree Codex版の機能とは分けて確認してください。

- **MCPサーバー化** — N3MCをMCPサーバーとして公開し、他のAIツールから記憶にアクセス
- **PostgreSQL移行** — SQLiteからPostgreSQL + pgvectorへ（組織のチームで使う既製の版は、PostgreSQL の N3MC Pro、`n3mc-pro-postgres`）
- **カスタム検索ロジック** — バイアス係数やランキング式の調整
- **他のembeddingモデル** — 用途に合わせたモデルへの差し替え
- **キーワード検索のトークナイザー** — 既定のキーワードの索引（FTS5 `trigram` と、日本語・中国語・韓国語のための 2 文字の索引）は、空白で区切らない言語でも、英語のような言語でも動くように選んでいます。最終的なトークナイザーは、ご自分の言語・環境に合わせて直してください（例: 英語中心なら語形変化をまとめる `porter unicode61`、日本語の精度を上げるなら形態素解析）。起動のときに索引を `trigram` に作り直す確認の直しと、既存の DB の全文検索の索引の作り直しも含めて、Codex に相談すれば対応できます
- **ID階層の拡張** — `project_id`や`tag`など、分類フィールドを自由に追加
- **PDF取込** — PDFからテキストを抽出し、検索可能な記憶として保存
- **ハッシュタグ対応** — Codexが記憶に `#タグ` を自動付与して絞り込み検索（例: `--search "#AWS"`）。既存のFTSで動作し、DB変更不要

指示書をCodexに読ませて追加したい内容を相談し、指示書の更新・コード生成・確認テストまで行ってください。
